# Userr delivery plan (subtask expansion of `phases.md`)

> `phases.md` in this folder is canonical: one numbered phase = one PR, and a
> phase ships only when its tests pass. This file expands each phase into
> reviewable subtasks with pointers to the normative catalogs. Where any detail
> below conflicts with the root invariants (host-owned auth, domain-shaped
> adapters, asynchronous optional AI, zero-dep core, no hosted runtime), the root
> wins.
>
> Normative specs: [product-spec](./product-spec.md) · [reference-architecture](./reference-architecture.md) ·
> [feature-catalog](./feature-catalog.md) · [adapter-matrix](./adapter-matrix.md) ·
> [integration-catalog](./integration-catalog.md) · [webhook-protocol](./webhook-protocol.md) ·
> [dependency-catalog](./dependency-catalog.md) · [links](./links.md)

## Completed foundation (shipped)

- [x] Repository contract, MIT license, npm workspaces, base CI, fixtures,
  documentation hub, portable rules (`@userr/core` types + transition/merge/
  lexical-similarity tests), React primitives (provider/card/form), safe CLI
  skeleton (`init`/`doctor`/`upgrade`, `--dry-run`, manifest, non-overwrite policy).

## Phase 1 — Convex headless reference (current)

Goal: a complete, host-wrapped Convex component other phases can build on.
Spec: [reference-architecture](./reference-architecture.md) (Convex rules, data model).

- [ ] 1.1 Cursor pagination compatible with components (`convex-helpers`
  `paginator`; built-in `.paginate()` does not work inside components).
- [ ] 1.2 Comment mutations (create/reply/edit-by-author, depth guard, tombstone
  soft-delete) + subscription mutations (subscribe/unsubscribe with
  notify-comments/status flags).
- [ ] 1.3 Status transitions + moderation enforced in the host wrapper
  (`resolveActorId`/`canModerate`); component takes opaque actor IDs only.
- [ ] 1.4 Public API validators (`args` + `returns` on every component function;
  unvalidated boundaries degrade to `any`).
- [ ] 1.5 `convex-test` coverage per mutation (vote atomicity, merge vote transfer,
  canonical readability) + example app + seed script.
- [ ] 1.6 Async embedding hook: `embeddingState pending|ready|disabled`,
  scheduled enrichment job; creation and reads never wait for a provider.
- [ ] 1.7 Define the shared domain conformance suite (transition guards, merge
  invariants, vote uniqueness, cursor paging) that Phase 2 must also pass.

## Phase 2 — Postgres/Neon headless parity

Goal: second backend proving the `FeedbackRepository` contract is portable.
Spec: [adapter-matrix](./adapter-matrix.md) (Tier 0 #2).

- [ ] 2.1 Drizzle schema 1:1 with the Convex tables (boards/items/votes/comments/
  events/subscriptions + tags/roadmaps/changelog/webhooks/apiKeys from the
  [reference data model](./reference-architecture.md)); `pgvector` setup docs;
  trigram + HNSW indexes.
- [ ] 2.2 Transactional vote/merge behavior matching the conformance suite;
  normalize driver row-count differences in the adapter (BetterAuth
  drizzle-adapter pattern).
- [ ] 2.3 Next.js route-handler factory (`toNextJsHandler(userr) → {GET,POST}`)
  + `/api/v1/*` routes; BYO-auth integration points (host resolves identity,
  adapter takes opaque IDs — port the shape of UserCue `auth.ts/permissions.ts`,
  not its code).
- [ ] 2.4 Run the Phase 1 conformance suite green against Postgres.
- [ ] 2.5 Document polling/SWR baseline honestly; no cross-backend "live" claim.

## Phase 3 — Public portal and updates

Goal: owned Next.js surfaces generated by the CLI.
Spec: [feature-catalog](./feature-catalog.md) (Feedback/Portal/Roadmap/Updates rows).

- [ ] 3.1 Board list + detail + comments + search + lexical duplicate suggestions
  (exact normalized-title + similar; no AI dependency).
- [ ] 3.2 Roadmap lanes from configured statuses; changelog list + entry +
  RSS/sitemap/SEO; subscriptions wired to host email hooks.
- [ ] 3.3 i18n message dictionary (no i18n runtime), theme tokens, dark default,
  accessible primitives (Radix when needed, never Tailwind as a runtime requirement).
- [ ] 3.4 CLI `add` command + generated-file ownership markers + non-overwriting
  upgrades, for Convex and Neon.

## Phase 4 — Triage and closed loop

Goal: the admin experience that keeps teams off Canny.
Spec: [feature-catalog](./feature-catalog.md) (Triage row) + [webhook-protocol](./webhook-protocol.md).

- [ ] 4.1 Inbox (unreviewed sorted by votes), keyboard workflow, bulk
  close/spam, trust/block, moderation queue, activity/audit log.
- [ ] 4.2 Merge review panel (lexical/semantic candidates, vote transfer preview,
  voter notify; admin confirms — never auto-merge destructively).
- [ ] 4.3 Roadmap board (DnD lane ordering persisted), prioritization views,
  changelog publisher prompting on ship.
- [ ] 4.4 Generic signed webhook outbox first (canonical events, HMAC-SHA256,
  idempotency keys, bounded retries, deliveries ledger), then host email hooks
  for subscriber notifications.

## Phase 5 — Contextual widget and capture

Goal: zero-dependency browser launcher + React wrapper.
Spec: [feature-catalog](./feature-catalog.md) (Capture row); references: BugDrop
(MIT) and Reflet behavior, clean-room only.

- [ ] 5.1 IIFE bundle with zero runtime deps; `data-*` config + JS API
  (`open/close/hide/show/setTheme`); Shadow DOM isolation; welcome-once +
  dismissible launcher.
- [ ] 5.2 Opt-in screenshots with annotation + privacy masking/redaction,
  element context (selector + component stack), console-log bundle behind
  explicit consent; metadata allowlist; retention controls; no session replay.
- [ ] 5.3 Declarative flow builder (forms/screens/conditions) + headless submit
  for fully custom UI; server-controlled labels/statuses (fail closed).
- [ ] 5.4 Rate limits + HMAC host tokens + redacted URLs; Playwright E2E +
  privacy tests.

## Phase 6 — Intelligence, integrations, and site

Goal: optional AI, native plugins, static front door.
Spec: [integration-catalog](./integration-catalog.md) + [webhook-protocol](./webhook-protocol.md).

- [ ] 6.1 Asynchronous BYO embeddings (bring provider + key, or custom provider
  impl), semantic duplicate candidates, AI summaries/draft replies; provider
  failure always falls back to lexical — never blocks.
- [ ] 6.2 Native plugins in priority order: generic webhook (already Phase 4),
  then Slack, Discord (`messageId` PATCH sync, slash commands), GitHub (two-way
  issue sync), Linear; each with `server + ui` + conformance tests.
- [ ] 6.3 Static docs + stack picker site (outputs one `userr init` command);
  it never receives feedback rows, DB URLs, API keys, or secrets.
- [ ] 6.4 Importers (Canny/Fider CSV) + `sync-counts`/`reset` CLIs.

## Phase 7 — Demand-gated extensions (do not build speculatively)

Gate: 3+ real user asks or a maintainer dogfoods it. Spec: [adapter-matrix](./adapter-matrix.md)
(Tiers 1–2) + [feature-catalog](./feature-catalog.md) (Surveys/Support rows).

- [ ] 7.1 Supabase adapter (SQL migrations + RLS + private Realtime channel
  authorization) with documented vector/realtime behavior.
- [ ] 7.2 SQLite (Turso/D1) / MySQL (PlanetScale) only with trigram fallback
  for dedup and honest polling story.
- [ ] 7.3 Surveys/outbound (NPS/CSAT, targeting, frequency caps), then help
  center/support, MCP server, mobile SDKs, multi-brand, custom domains, RTL,
  plugin SDK — each behind its own adoption signal.
